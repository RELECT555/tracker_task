# ТЗ: Фильтр плана по итерации Azure DevOps

Дата: 2026-11-16. Статус: черновик на согласование.

## 0. Зачем

Переключатель «квартал / месяц» на странице плана сейчас меняет только часы и счётчики. Список эпиков и фич в таблице всегда один и тот же: все карточки проекта (`RoadmapPage.tsx:1695`, `summary.ts:121`). В Azure команды раскладывают работу по итерациям кварталов. План должен показывать то же, что Azure: в Q4 2026 видны карточки итерации Q4 2026.

`System.IterationPath` уже запрашивается при импорте (`roadmap-work-item-import.service.ts:111`), но не сохраняется.

### Цели
1. В выбранном квартале таблица показывает эпики и фичи, у которых итерация в Azure относится к этому кварталу.
2. Работа, у которой есть план или факт в периоде, но итерация другая, не теряется: показываем её с пометкой «вне итерации».
3. Проекты, которые не ведут итерации по кварталам, выглядят как сейчас.

### Не цели
- Отдельный фильтр по месяцам через спринты. Месяц показывает набор карточек своего квартала.
- Фильтрация тасков (в таблице их нет).
- Изменение счётчиков и итогов. Они уже считаются по плану и факту периода (`getRoadmapSummary`), и мы их не трогаем.

### Анти-цели
- Строки таблицы не сходятся с итогами плана и факта наверху. Значит, нельзя прятать карточку, у которой в периоде есть план или факт.
- Проект без квартальных итераций превращается в пустую таблицу.

## 1. Подходы

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| **A (выбран)** | Сохраняем `iterationPath` карточки. Сервер находит путь итерации квартала через существующую `quarterIterationPath`, клиент сравнивает пути по префиксу | Одно правило «что такое Q4» и для фильтра, и для записи тасков в Azure | Месяц не уже квартала |
| B | Сохраняем у карточки даты её итерации, фильтруем по пересечению дат | Работает и для спринтов по месяцам | Если в Azure поменять даты итерации, инкрементальный синк этого не заметит, и данные устареют. Появится второе правило, которое может разойтись с записью |
| C | Отдаём клиенту всё дерево итераций | Гибко | Логика дублируется на фронте, ответ плана тяжелее |

Выбран A, решение пользователя.

## 2. Решение

### 2.1 Данные
- Новая колонка `RoadmapWorkItem.iterationPath String? @map("iteration_path") @db.VarChar(1000)` и миграция.
- `upsert` в импорте пишет `fields['System.IterationPath']`.
- У существующих карточек поле пустое до следующего импорта. Пока у всех плановых карточек проекта (эпики и фичи) `iterationPath` пустой, проект считается «ещё не загружен» и не фильтруется (§2.3). *Моё решение:* полный пересинк не форсируем. Если нужно сразу, достаточно нажать ручную синхронизацию. Проверить при реализации, что ручной синк перечитывает все карточки, а не только изменённые. Если нет, добавить одноразовое дообогащение по образцу `missingAssigneeIds` (`roadmap.service.ts:358`).

### 2.2 API
- `quarterIterationPath` становится доступной снаружи сервиса синка: публичный метод либо вынос в отдельный хелпер с тем же кешем дерева итераций.
- Новый эндпоинт `GET projects/:projectId/iteration?quarterKey=YYYY-Qn` возвращает `{ iterationPath: string | null }`. Доступ такой же, как у `GET projects/:projectId/plan`. Ошибки Azure не должны ронять страницу: при ошибке отдаём `null`, это означает «не фильтруем».
- План (`getProjectPlan`) отдаёт `iterationPath` каждой карточки. Колонка придёт сама через `include`, проверить DTO и типы фронта.

### 2.3 Правило видимости (общая функция в `packages/shared/src/roadmap-plan`)
Входные данные: карточки, путь итерации квартала (`null`, если не найден) и активность карточки в периоде (план или факт, как `hasActivity` в `summary.ts:127`).

- Путь квартала `null` или итерации у проекта не загружены: видны все карточки, пометок нет (как сейчас).
- Фича **в итерации**, если её путь равен пути квартала или начинается с `путь + '\'` (сравнение без учёта регистра).
- Фича видна, если она в итерации или у неё есть активность в периоде. Если видна только благодаря активности, ставим пометку «вне итерации».
- Эпик виден, если он сам в итерации, у него есть активность или видна хоть одна его фича. Пометку эпик получает, только если сам не в итерации, но у него есть собственная активность. Если эпик виден только из-за своих фич, пометки нет.
- Карточки без итерации или в корне проекта считаются «не в итерации»: показываем их только при активности и с пометкой.
- Фильтр по статусу работает поверх этого правила, как сейчас.

### 2.4 Интерфейс
- Пометка «вне итерации» — небольшой бейдж в ячейке названия. В подсказке указана итерация карточки из Azure, например «Итерация: Проект\2026\Q3».
- Если путь квартала не найден, в строке над таблицей пишем «Итерация квартала в Azure не найдена — показаны все карточки».
- Обзор «Все проекты» не трогаем: там нет списка карточек, только счётчики.

## 3. Проверка
- Unit-тесты на правило видимости: в итерации, во вложенной итерации, вне итерации с активностью или без неё, без итерации, путь `null`, эпик только через фичу, разный регистр.
- Тест импорта: `iterationPath` сохраняется.
- Тест эндпоинта: при ошибке Azure возвращается `null`.
- Ручная проверка на демо или на реальном проекте: переключение Q3/Q4 меняет список, бейдж на месте.

## 4. Оставлено исполнителю
- Точное имя и место хелпера, форма бейджа в рамках текущих UI-компонентов.
- Демо-режим (`roadmapDemoStore`): либо прописать демо-карточкам итерации, либо возвращать `null` (без фильтра). *Моё решение:* `null`.
